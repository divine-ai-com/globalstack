## Highest-value remaining evidence

1. **Independent workload selection.** Select externally authored Azure scenarios before executing them. Record inclusion and exclusion rules, pinned sources, license, expected behavior, and all failures. The refined claims case now avoids the workflow engine, but it is still first-party and does not complete independent selection. A few distinct architectures provide more evidence than many repeated variants of these two flows. External authoring reduces shared assumptions; it does not itself prove Azure equivalence.
2. **Independent reproduction.** A person who did not implement the scenarios should rerun the artifact on a clean host and review the expected outcomes. Retain discrepancies and environment details. Another run by the implementer or on the same host is not independent reproduction.
3. **Paired live Azure evidence, if fidelity is a paper claim.** Execute the same declared scenarios against Azure and the local system. Pin API versions, retain sanitized observations and side effects, define allowed normalization, document mismatches, and verify cleanup. Asynchronous Azure delivery needs an explicit deadline and late/duplicate observation policy. Requires access and an agreed resource/cost budget; no such run is part of the present evidence.
4. **Semantic breadth.** Add delayed delivery, retries, batching, and legitimate fan-out only when implemented and testable. Include negative and restoration controls. Retain unsupported cases as unsupported instead of converting them into passes.

Items 1 and 2 are the preferred low-cost next steps. Item 3 is necessary for empirical live-cloud fidelity claims, not a formal prerequisite for every scoped systems paper. Cloud equivalence, production readiness, and statistical generalization remain outside the present contribution.
