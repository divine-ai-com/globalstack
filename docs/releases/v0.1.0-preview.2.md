# v0.1.0-preview.2 validation scope

This source preview is for trusted workloads on isolated development hosts. It provides a bounded Azure management API and selected executable service paths. It is not a complete Azure replacement or a production security boundary.

Preview 1 was moved back to draft after a defective severity checker concealed existing high and critical CodeQL findings. Its tag remains unchanged. This replacement corrects the checker and the reviewed runtime issues. See the [security correction](../product/SECURITY-REVIEW.md) and [individual findings](../product/SECURITY-FINDINGS-2026-11-04.md).

## Evidence

The [validation record](v0.1.0-preview.2-validation.json) records the tested revision, client versions, platform results and limits. Release assets include that record, provider lifecycle operations, the JavaScript SBOM, the complete CodeQL report, validation toolchain recipes and checksums. The post-merge security result is recorded separately before publication. Raw working directories, credentials and token response files are excluded.

| Check | Result and scope |
|---|---|
| Local conformance | 556 passed, one explicitly Docker-dependent Kubernetes test skipped |
| Repository policy and security-gate tests | 19 passed |
| GCP unit tests | 17 passed; no live GCP validation |
| Selected service packs | Key Vault 99, Event Grid 45, Logic Apps 62; Files, WAF and Storage counts are in the validation record |
| Native IaC samples | One sample in each of nine platforms; all seven stages and cleanup required |
| Distribution | Source archive without Git metadata and locally built container: deploy, read, reject unsupported resources, delete |
| Static analysis | Zero high or critical findings; 19 raw medium findings, including one previously dismissed fixture-replay finding |

These suites overlap. Their counts are not a denominator for Azure coverage. The remaining static-analysis findings describe reviewed fixture replay, capture writes, credential exchange or optional model-generation flows. They remain visible in the report. No scanner rule or directory was excluded, and no severity threshold was lowered.

The native matrix covers Terraform and OpenTofu with AzAPI, Pulumi TypeScript, Python and YAML, Ansible, Azure CLI REST, Bicep and ARM JSON. Each sample runs build, lint, unit tests, deploy, provider lifecycle, integration tests and destroy. The lifecycle report records 50 provider operations. These native samples do not establish arbitrary application event delivery or AzureRM compatibility.

Three unmodified Microsoft Quickstart templates remain pinned by revision and SHA-256 digest, with their MIT license retained. Storage is a management-plane example. Key Vault includes an HTTP secret read. Event Grid includes HTTP publication, exact event ID and payload checks at a local webhook, deleted-subscription and wrong-destination controls, and restored delivery. Those controls distinguish successful deployment from working wiring. Azure asynchronous delivery, retries, filtering and dead-letter behavior are not established.

## Reproduction and review

Use the [README quickstart](../../README.md), then run:

```bash
npm ci
npm run check:local
npm run test:repository
npm run test:gcp:unit
npm run test:services:local
npm run demo
```

The native matrix is separate: `npm run smoke:platform-runners` requires Docker and downloaded IaC tools. Validation used shared toolchain images to reduce duplicated layers. The recipes, observed versions and HCL provider lockfiles are retained. This does not establish that every standalone runner Dockerfile builds. Mutable installers and package ranges prevent a byte-for-byte reproducibility claim.

Tests ran on Linux x86_64 with a four-CPU, approximately 31 GiB RAM host. CI runs Node.js 22 and 24. Other host architectures, minimum resources and sustained-load capacity have not been established. Native runs used three isolated groups with a disk guard above the required 40 GiB reserve. No live Azure deployments or paid model calls were made.

Concurrent validation exposed a Logic Apps test that assumed its first GET would occur before a 10 ms delay elapsed. The workflow had correctly completed by that read. An injected clock now controls elapsed time in the service test while the default runtime still uses wall-clock time. The corrected test verifies running, completed and cancelled states. The failed attempt is recorded separately.

Manual review covered the full diff and bot comments. Security regressions check proxy destination confinement, redirect rejection, request/response size limits, binary data preservation, bounded file allocations, rejection of arbitrary Key Vault tokens, prototype-pollution rejection, generic internal errors and credential-header redaction.

## Remaining limits

- The broader historical 30-service validator still requires missing artifacts and optional backend matrices. It has not passed for this preview.
- Registered capabilities vary in depth. ARM expressions, deployment scopes, runtime backends and cross-service combinations remain partial.
- The local development identity is not Azure RBAC enforcement. State is ephemeral; durable state, network isolation and production multi-tenant security are outside this preview.
- The current live Azure differential harness covers selected AKS status/error cases. Full response, side-effect and event-flow comparison remains future work. The weekly API specification watcher is a review signal, not proof of continuing behavioral agreement.
- Capture-wide privacy review and optional runtime-image licensing remain incomplete. The source release does not redistribute those images or claim regulatory certification.

A paper can report the architecture, declared test scope and observed defects. A numerical Azure-accuracy claim requires a versioned test inventory, independent live evidence, failure accounting and repeated comparisons that these local results do not provide.
