# v0.1.0-preview.1 validation scope

This source preview is for trusted workloads on isolated development hosts. It provides a bounded local Azure management API and selected executable service paths. It is not a complete Azure replacement or a production security boundary.

## Evidence and reproduction

The accompanying [validation record](v0.1.0-preview.1-validation.json), also attached as `validation.json`, records the tested runtime revision, native platform results, client versions and known limits. The release SBOM inventories JavaScript dependencies. The toolchain archive contains the shared validation-image recipes and provider lockfiles. Raw execution directories, local credentials and token response files are not release assets.

The runtime was tested on Linux x86_64. Local CI also runs on Node.js 22 and 24. Other host architectures and operating systems are not established by this release. The management state is ephemeral and disappears on restart. Resource minima and sustained-load capacity have not been measured.

Use the [README quickstart](../../README.md) for the source and container examples. A source archive without Git metadata and the locally built container both passed deployment, readback, unsupported-resource rejection and cleanup checks. The archive check installed dependencies with `npm ci --ignore-scripts`; CI separately exercises the standard `npm ci` path. The source release does not distribute optional third-party runtime images.

Run the local checks with:

```bash
npm ci
npm run check:local
npm run test:repository
npm run test:services:local
npm run demo
```

The native matrix is separate and needs Docker plus downloaded IaC tooling:

```bash
npm run smoke:platform-runners
```

That command builds the platform images when needed. The recorded validation used a shared Terraform/Azure CLI base with added OpenTofu, Pulumi, Ansible and Bicep dependencies to reduce duplicated image layers. Each platform still ran its own sample and native deployment commands. This validates those toolchain combinations, not every standalone runner Dockerfile. Mutable upstream installers and dependency ranges remain a reproducibility limitation; the observed versions and HCL provider lockfiles are retained.

## What was exercised

Local conformance checks passed 548 tests, with one explicitly Docker-dependent test skipped. Repository checks passed 17 tests. The selected service packs passed 99 Key Vault cases, 45 Event Grid cases and 62 Logic Apps cases. These are separate suites with overlapping behavior, not a summed coverage denominator. The service packs ran without their nested platform matrices; the native matrix was run separately.

Three unmodified Microsoft Quickstart templates are pinned by revision and SHA-256 digest, with their MIT license retained:

| Template | Observed behavior | Boundary |
|---|---|---|
| Storage account | Deploy, resource properties, readback and deletion | No storage data-plane operations in this case |
| Key Vault with secret | Deploy, default location and tenant resolution, read secret over HTTP, delete | No claim of Azure RBAC enforcement |
| Event Grid | Deploy topic and scoped subscription, publish unique events, receive identical payloads at a local webhook | No live Azure comparison or asynchronous delivery guarantee |

The Event Grid negative controls remove the subscription and then point it at a wrong destination. Publication still succeeds, but the expected destination receives no matching event. Restoring the correct destination restores delivery. This caught a runtime bug where deleting a scoped subscription left webhook delivery active. Resource existence alone would not detect that defect.

All nine native platform samples passed on runtime revision `3991f83952d0187b223950b857ceb0aaae315835`. The checks require all seven stages: build, lint, unit tests, deploy, provider lifecycle, integration tests and destroy. These runner samples establish native deployment and lifecycle compatibility for their selected resources. Their integration stage is not evidence of arbitrary application event flows. Terraform and OpenTofu use AzAPI; AzureRM is unverified.

## Failed attempts and review findings

Validation records retain setup failures rather than counting them as emulator failures or successful runs. An Ansible image export stopped at the disk guard and passed on retry after storage was expanded. A Bicep attempt reused an image without ICU and failed before deployment; the correct CLI toolchain includes ICU. Those attempts are excluded from final successful-run timings.

The broader `npm run validate` command was not green for this scope. It requires the full historical 30-service smoke artifacts and nested matrices, including optional external backends. Missing artifacts remain missing; no synthetic success reports were added. The smaller preview checks above must not be described as a pass of that broader validator.

PR review included the full diff, bot comments and CodeQL findings. The fixture-to-loopback HTTP finding was reviewed as a false positive for this test path, with redirects disabled and no scanner exclusion. Copilot's quota failure was not counted as a completed review. See the [security review](../product/SECURITY-REVIEW.md).

The SBOM contains 158 components. Three optional packages lacked license metadata in that output: `buildcheck`, `cpu-features` and `ssh2`. Their installed package license files contain MIT terms; the bundled `cpu_features` dependency has its own license file. This inspection does not establish redistribution rights for every optional external runtime image.

## Remaining support and research gaps

- ARM expression and deployment-scope support is partial. Only the documented resource extensions in the deployment resource group are covered by the new scope handling.
- No claim is made that all 30 registered capabilities implement their full Azure service surface.
- Event Grid retry timing, filters, ordering and dead-letter behavior are outside the demonstrated webhook flow. Local delivery currently completes before publication returns.
- Azure identity enforcement, network isolation, durable state, high availability and performance equivalence remain outside this preview.
- The existing AKS differential harness compares selected status and error-code outcomes. Comprehensive body, side-effect and cross-service comparisons against live Azure remain future work.
- The weekly API specification watcher is a read-only review signal. A stable API specification does not prove stable service behavior.
- Privacy review across every historical capture family and optional runtime licensing remain stable-release work. This is not a compliance certification.

A paper can describe the implemented architecture, scoped tests and observed defects. Claims of broad Azure equivalence or a numerical accuracy target require a declared test inventory, independent live Azure evidence, failure accounting and repeatable results that this preview does not yet provide.
